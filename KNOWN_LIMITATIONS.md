# Known limitations

Current validation and exact test/command evidence are in [docs/VALIDATION.md](docs/VALIDATION.md). This is a reviewable prototype; **production V1 readiness is not established**.

1. **External LLM live run is BLOCKED/unconfigured.** The real HTTP adapter is tested against a controlled loopback fixture. No real external credentials were configured, no private notes were scanned, and no external semantic success is claimed. FakeLLM/HTTP fixtures are scripted and cannot establish semantic precision, recall or entity resolution accuracy. SPEC §13.2 goals remain NOT_MEASURED; tokens are recorded only if an API supplies bounded numeric usage, cost remains null.
2. **Conservative rules are incomplete semantics.** Exact quotes, schema validation and lexical guards do not establish arbitrary entailment. Modality/polarity/time and identity handling may over-defer or miss novel phrasing. Real precision/recall requires an authorized, manually labeled corpus and a configured model. Long synthetic notes test sequencing/digest, not extraction recall. No real LLM auditor, full temporal reasoning or ontology reconciliation is implemented.
3. **Legacy semantic reconciliation is partial.** Imported claims use full-ledger canonical matching. Actual observe `relevant_engrams` enter the LLM as unstructured possible matches; they are not translated into a complete structured external-candidate conflict/dedup gate. A legacy equivalent/conflict can therefore remain undetected. Explicit structured candidates can defer obvious matches, but retrieval is not exhaustive and does not authorize merge/update. Product native entity lookup uses an explicit local fallback; the separate capability smoke verifies the optional tools only. Native name aggregates are not identities.
4. **Pinned exhaustive marker recovery is UNSUPPORTED.** v0.9.0 active listing omits archived/deleted states; deleted listing returns at most 100 of 101 synthetic tombstones and ignores offset. No exhaustive absence proof exists. Unknown POST outcomes become `needs_manual_repair`, with no automatic repeat POST. Known-ID repair verifies an independently obtained ID; it does not discover the ID. See [API matrix](integrations/muninn-compatibility.md).
5. **Known 4xx publication failures remain terminal/manual.** They are not retried or automatically abandoned. Unresolved attempted outbox operations block new jobs in the vault. There is currently no CLI abort/abandon action. Source/config/ledger changes during a partial commit fail closed and can require operator-led reconciliation.
6. **One authoritative ledger per backend/vault.** Idempotence/recovery depend on its retained outbox and identity/evidence projections. Independent ledgers, separate OS accounts or multiple hosts can create duplicates. The same-account vault lock is local, not distributed coordination; it also serializes equal vault names across different backend URLs.
7. **Linux publication is the tested platform.** Review/commit require `fcntl.flock`, `getuid`, ownership checks and `O_NOFOLLOW`. Windows returns `publication_lock_platform_unsupported`; macOS and other Unix filesystems/locking semantics are untested. Runtime packaging and portable HTTP/scan/plan code do not establish non-Linux publication readiness.
8. **Observe cognitive immutability is not proven.** Pinned live smoke observed unchanged exposed `access_count`/`last_access` over a two-second fixture window, including real hits; a full-key control also stayed unchanged. Hidden scoring feedback was not measured, and pinned source indicates potential GET feedback. Bounded observe access and explicit warnings remain necessary.
9. **Plaintext storage and explicit data disclosure.** Snapshots, SQLite and report evidence can contain private data; there is no encryption, content-secret scanner or tenant isolation. Explicit real LLM selection sends exact chunk text, scoped metadata/local paths and bounded committed/staged/retrieved context. Keys and raw error bodies are excluded from diagnostics; source text you intentionally select is not automatically redacted. A loopback LLM server may itself forward externally.
10. **Source lifecycle is bounded by observable eligibility.** Scan/precommit use one valid-subset policy with the original max-bytes; unchanged-ineligibility/skipped/hidden trees do not invalidate a plan. A newly eligible file does. Missing/ineligible documents leave current membership but history and committed memory remain, with `possibly_stale_source`. Removal does not revoke knowledge. No background watcher, rename matching or automatic truth maintenance exists. Historical schema3 collections need rescan; old plans need replan under current code/config. Scan and commit are not an atomic filesystem snapshot, so do not concurrently edit originals/snapshots or use adversarial mutable paths.
11. **Byte limits are not token/scalability guarantees.** Heading/paragraph chunks use approximate byte targets/overlap, not sentence/token boundaries. The complete serialized request is bounded (default 65536 bytes); oversized context entries/tails are omitted with counts. The exact source is never silently truncated. This can reduce context/recall or leave a chunk incomplete. Full local ledger resolution still loads full projections; discovery metadata and ledger state scale with collection size. Source bytes are read one document at a time, but this is not a streaming huge-vault implementation.
12. **Limited source formats and workflow.** Only UTF-8 `.md/.txt`; no PDF/OCR/attachments. Wikilinks/frontmatter are raw text, not a graph/schema. No UI, background sync, export command, automatic config-file loader, credential provisioning or production service deployment. `config.example.json` is a CLI option reference. Concurrent planning of the same job is not independently qualified; publication is serialized. Stable IDs remain stage1 SHA-256 prefixes rather than SPEC's suggested UUIDv7/ULID to preserve history.
13. **API/model scope.** OpenAI-compatible JSON-object chat completions, temperature 0 and nonstreaming `finish_reason:stop` are required. Vendor-specific schema/tool modes, unsupported model options, streaming, retry-after scheduling and pricing are not implemented. Bounded planner retry is initial+2 per incomplete chunk per invocation; a user can explicitly resume again. API 429/timeout/schema/anchor/malformed envelope failures preserve an incomplete checkpoint. No real provider/model compatibility beyond the controlled wire fixture is claimed.
14. **Live smoke scope.** Real pinned read/write uses temporary synthetic stores/keys with embeddings/enrichment disabled. It proves the tested REST/MCP contract, not semantic retrieval with embeddings, long-running cognitive behavior, distributed transactions or production capacity. Capability smoke archives/deletes its own disposable fixtures; product publication provides no destructive API. Existing stores and user sources were not touched.
